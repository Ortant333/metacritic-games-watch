# Metacritic Games Watch

Сервис тестового задания «AI Automation Engineer» (Скайтек): следит за новыми
играми Metacritic, ведёт свою базу, пишет резюме отзывов и подбирает летсплеи.

## Что делает

**Обязательная часть**

- Раз в час берёт 20 игр, которые сегодня ещё не обрабатывал, и добавляет их в
  базу (или обновляет, если игра уже есть).
- Выборка игр:
  1. первый заход каждого дня — 20 игр из раздела **New Releases** страницы
     [Games](https://www.metacritic.com/game/);
  2. следующие заходы — очередная страница раздела
     [SEE ALL](https://www.metacritic.com/browse/game/all/all/all-time/new/)
     (сортировка «Новые»);
  3. на следующий день выборка начинается заново с пункта 1.
- По каждой игре собирает: название, обложку, платформы с Metascore и
  Userscore (по каждой платформе отдельно), разработчика, описание, ссылку на
  видео (трейлер).
- Читает отзывы и пишет короткое резюме: что нравится игрокам, что нет.
  Резюме критиков и резюме игроков — раздельно. При повторных обходах резюме
  обновляется, когда появляются новые отзывы.
- Веб-интерфейс:
  - список загруженных игр с краткой информацией;
  - карточка игры с полной информацией;
  - фильтр по платформам;
  - поиск по названию;
  - сортировка по рейтингу (Metascore / Userscore, по возрастанию и убыванию);
  - похожие игры из базы сервиса — клик по названию открывает карточку.

**Дополнительная часть 1** — для каждой игры ищет летсплеи на YouTube, берёт
самый популярный (по просмотрам), превращает рассказ блоггера в текст
(расшифровка субтитров) и добавляет к информации об игре заключение со
ссылкой на ролик.

**Дополнительная часть 2** — страница «Мониторинг»: статусы воркеров, счётчики
обработанных записей и журнал в реальном времени (обновление раз в 2 секунды),
плюс кнопка принудительного запуска обработки.

## Как устроено

| Модуль | Назначение |
|---|---|
| `mc.py` | клиент Metacritic: вежливые запросы (пауза между запросами, повторы на 429/5xx), разбор страниц |
| `nuxtdata.py` | разборщик `__NUXT_DATA__` — все данные Metacritic приходят в payload Nuxt (devalue-формат) |
| `db.py` | SQLite (WAL): игры, платформы, отзывы, резюме, летсплеи, заходы, состояние дня |
| `llm.py` | резюме отзывов и заключения по летсплеям через любой OpenAI-совместимый API; дневной бюджет вызовов; извлекающий fallback без LLM |
| `letsplay.py` | YouTube: поиск летсплея (самый популярный по просмотрам), расшифровка рассказа через субтитры |
| `similar.py` | похожие игры: TF-IDF + косинусная мера по названию/жанрам/описанию |
| `worker.py` | почасовой заход: выборка партии -> сбор данных -> резюме -> летсплеи |
| `webapp.py` | FastAPI: UI + JSON API |
| `templates/`, `static/` | вёрстка |

Почему так: Metacritic отдаёт готовую структуру в `__NUXT_DATA__`, поэтому
парсинг идёт по данным, а не по классам вёрстки; это устойчиво к смене CSS.
Юзер-оценка каждой платформы живёт на странице
`/game/<slug>/user-reviews/?platform=<platform>` — по ней собираются
оставшиеся оценки.

## Запуск

```bash
python3 -m venv venv
venv/bin/pip install -r requirements.txt
cp .env.example .env        # вписать LLM_API_KEY (или оставить пустым - будет fallback)
venv/bin/python main.py     # http://<хост>:8095
```

Переменные окружения (`.env`):

| Переменная | По умолчанию | Смысл |
|---|---|---|
| `MC_PORT` | 8095 | порт веб-интерфейса |
| `MC_DB` | `data/mc.db` | путь к базе SQLite |
| `GAMES_PER_RUN` | 20 | сколько новых игр брать за один заход |
| `LETSPLAY_PER_RUN` | 2 | сколько летсплеев дообрабатывать за заход |
| `LLM_API_BASE` | — | база OpenAI-совместимого API |
| `LLM_API_KEY` | — | ключ; без него резюме пишутся извлекающим способом |
| `LLM_MODEL` | mimo-v2.6-flash | модель |
| `LLM_DAILY_BUDGET` | 120 | максимум LLM-вызовов в сутки |

## API

- `GET /api/status` — состояние воркеров, счётчики, история заходов;
- `POST /api/run-now` — принудительный запуск обработки.

## Развёртывание

`deploy/install.sh` ставит зависимости, systemd-сервис `skytek-mc.service` и
запускает сервис. Внутренний планировщик дёргает обход раз в час.
